# Живая проверка 3.5: маршрутизация

Маршрутизация решает, что идёт через сервер, а что напрямую: пресет («Весь трафик через VPN», «Обход для России»,
«Только выбранные приложения»), флажок «Локальная сеть напрямую» и свои правила. Раздел — «Настройки → Маршрутизация».
Правила действуют в обоих режимах; изменения — со следующего подключения (при подключении появляется «Переподключить»).

Признак пути — две страницы, которые показывают ваш внешний адрес:
- `https://2ip.ru` — российский сайт (зона .ru): при обходе для России открывается **напрямую** (ваш обычный адрес);
- `https://www.cloudflare.com/cdn-cgi/trace` — зарубежный: **через сервер** (адрес сервера, строка `ip=`).

Браузер держит открытые соединения: после смены правил и переподключения закройте вкладку и откройте страницу заново
(или Ctrl+F5).

**Службу переустановите из этой сборки** («Настройки → Служба KHORS → Удалить», затем «Установить»): версия протокола
изменилась. Гео-базы должны быть загружены («Настройки → Гео-базы», проверка 3.6).

110. Откройте «Настройки → Маршрутизация». **Ожидается:** выбран «Весь трафик через VPN», флажок «Локальная сеть
     напрямую» стоит, «Своих правил нет.».
111. Режим «Системный прокси», подключитесь. **Ожидается:** обе страницы показывают адрес сервера.
112. Не отключаясь, выберите «Обход для России». **Ожидается:** жёлтая строка «Маршрутизация изменена — она вступит
     в силу после переподключения» и кнопка «Переподключить». Нажмите её. **Ожидается:** строка исчезла; 2ip.ru — ваш
     обычный адрес, cloudflare — адрес сервера.
113. Отключитесь, переключите режим на TUN, подключитесь. **Ожидается:** то же, что в шаге 112. Российские сайты
     (yandex.ru, vk.com, gosuslugi.ru) открываются без задержек — имена для них разрешает DNS провайдера (по DHCP).
     Если российские сайты в TUN не открываются, а зарубежные открываются — пришлите лог из «Журнала» (уровень лога
     ядра — debug).
114. Добавьте правило: «Домен и поддомены», `2ip.ru`, «Через сервер» → «Добавить правило», переподключитесь.
     **Ожидается:** 2ip.ru — адрес сервера (своё правило раньше пресета). Затем правило «Домен и поддомены»,
     `cloudflare.com`, «Напрямую», переподключитесь. **Ожидается:** cloudflare — ваш обычный адрес.
115. Правило «Слово в имени», `example`, «Блокировать», переподключитесь. **Ожидается:** `https://example.com`
     не открывается, остальные сайты — открываются.
116. Проверка ввода (правило не добавляется, красная строка):
     - «Домен», `https://example.com/path` — «Это не имя сайта…»;
     - «IP или подсеть», `203.0.113.7/24` — «…без лишних битов…»;
     - «Категория сайтов (geosite)», `no-such-category` — «В загруженной гео-базе нет категории…»;
     - повторно то же правило, что уже есть, — «Такое правило уже есть.».
     В поле значения для «Категория сайтов (geosite)» и «Страна IP (geoip)» при наборе появляются подсказки из базы.
117. Стрелки «Выше»/«Ниже» меняют порядок правил, крестик удаляет. У первого правила «Выше» и у последнего «Ниже» —
     бледные и не нажимаются. Перезапустите KHORS. **Ожидается:** пресет, флажок и правила в том же порядке.
118. Только TUN: выберите «Только выбранные приложения», добавьте правило «Процесс (только TUN)», `msedge.exe`,
     «Через сервер», переподключитесь в режиме TUN. **Ожидается:** в Edge cloudflare — адрес сервера; в командной
     строке `curl.exe https://www.cloudflare.com/cdn-cgi/trace` — ваш обычный адрес (curl идёт напрямую).
     В режиме «Системный прокси» этот пресет работает как «Весь трафик через VPN».
119. Без гео-баз: снимите «Проверять обновления раз в сутки» (раздел «Гео-базы»), закройте KHORS (трей → «Выход»),
     переименуйте папку `%APPDATA%\KHORS\geo` в `geo-off`. Запустите KHORS, «Обход для России», режим «Системный
     прокси», подключитесь. **Ожидается:** подключение работает, на странице «Подключение» жёлтая строка «Часть правил
     маршрутизации не действует: в гео-базе нет geosite:category-ru, geoip:ru…»; обе страницы — адрес сервера.
     Закройте KHORS, верните имя папки `geo`, верните флажок.
120. Режим «Системный прокси»: снимите «Локальная сеть напрямую», переподключитесь. **Ожидается:** страница роутера
     (обычно `http://192.168.0.1` или `http://192.168.1.1`) не открывается или открывается долго — запрос ушёл на сервер.
     Верните флажок, переподключитесь — страница роутера открывается. (Необязательно: то же в режиме TUN — запишите,
     открывается ли роутер; своя подсеть адаптера может идти мимо туннеля по маршруту Windows при любом положении флажка.)
121. Верните «Весь трафик через VPN» и удалите свои правила.

Что прислать: результаты шагов 110–121; при ошибке — текст красной или жёлтой строки и лог из «Журнала»
(он замаскирован). Ссылки на серверы не присылайте.
